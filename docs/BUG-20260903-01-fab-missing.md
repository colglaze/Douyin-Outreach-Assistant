# BUG-20260903-01 — 用户实测：主页无悬浮按钮、私信链路不可用

> 关联：REQ-20260903-02（修复与连刷自动化一并实施）；来源：2026-09-03 用户实测反馈。

## 现象

用户在真实浏览器（Tampermonkey）使用 V0.3 时反馈：
1. 打开达人主页**连悬浮按钮都没有**；
2. 私信功能无法使用。

## 排查

- 开发 harness（CDP 注入）中 V0.3 悬浮按钮正常渲染，无法直接复现；
- 代码走查发现结构性风险：旧版 bootstrap 顺序为 `openDB -> loadSettings -> ... -> fab`，
  **任何前置步骤失败（如 IndexedDB 被禁）都会导致悬浮按钮完全不渲染，且无任何可见错误**；
- 另发现面板 `toggle()` 强制 `view='main'`，会把推荐页视图刷成空占位（本轮新增连刷视图后实测复现）；
- 设置视图「← 返回」按钮事件绑定丢失（历史编辑遗失），点击无效。

## 修复（V0.4.0）

1. **fab 先行**：悬浮按钮在 bootstrap 最前面渲染，后续任何初始化失败按钮仍可见；
2. **错误横幅**：初始化失败时页面左下角显示红色横幅（含版本号与错误信息），便于用户截图反馈；
3. `toggle()` 不再强制重置视图；新增 `lastContentView` 记录，「← 返回」正确恢复 main/feed 视图；
4. 补回 `#doa-back` 点击事件绑定。

## 验证

harness（test-feed.mjs，匿名态推荐页）：
- 悬浮按钮出现 ✓；连刷视图渲染 ✓；未开启自动发送时启动被拒绝 ✓；
- 开关即时保存 IndexedDB 且跨会话持久 ✓；手动停止 ✓；连续失败自动停止 ✓；
- 全程 0 个脚本 pageerror ✓。

## 遗留

- 用户环境"无按钮"的确切根因未能远程确认（旧 dist 未更新 / IndexedDB 异常 / 注入失败均有可能），
  已由 fab-first + 错误横幅 + 版本号 v0.4.0 兜底；请用户更新 Tampermonkey 脚本后观察，
  若仍有异常按横幅信息反馈。
- 登录态连刷端到端（真实发送）需用户人工验证；发送按钮选择器仍未真实取证。

## 状态：已修复（待用户复测确认）
