# REQ-20260903-02 — 推荐页连刷自动化（自动进主页发私信）

> 关联：REQ-20260903-01（消息自动发送开关，本需求依赖它）、AGENTS.md 第 6 节（红线 v2）。
> 状态：已确认（2026-09-03 用户明确要求"推荐页自动连刷 -> 自动进主页 -> 自动发私信，文案可自定义"）。
> 2026-09-29 补充：REQ-20260929-05 增加用户明确选择的持续模式；本文件的单会话上限适用于限量模式。

## 1. 背景

用户实测反馈 V0.3 手动链路不可用（主页无悬浮按钮、私信链路不通），并明确提出
完整自动化诉求：**打开抖音推荐页 -> 开启自动连刷 -> 自动进入达人主页 -> 自动发送私信，
私信内容可自定义**。

这构成连续批量自动化，与 REQ-20260903-01 修订后的红线（禁止连续/批量发送）再次冲突。
用户作为产品负责人明确要求，故红线修订为 v2（见 AGENTS.md 第 6 节），
在保留保护机制的前提下实现。

**红线 v2**：连刷自动化必须用户手动启动/停止、依赖"消息自动发送"开关已开启、
跳过已联系达人、单会话发送上限、连续失败即停止；
仍禁止无人值守定时群发/跨会话自动恢复、验证码处理、风控绕过。

## 2. 纳入范围

| # | 功能 | 验收标准 |
|---|------|----------|
| 1 | 悬浮按钮兜底 | 任何初始化失败时悬浮按钮仍然可见，并显示错误横幅（修复"主页没有任何按钮"） |
| 2 | 自定义私信内容 | 设置新增"自定义私信内容"（支持 {{nickname}} 等变量，留空回退默认模板），持久化存储 |
| 3 | 推荐页面板视图 | 推荐页（/）面板显示连刷视图：状态/已发送计数/启动/停止按钮 |
| 4 | 连刷自动化 | 启动后循环：采集 feed 达人链接 -> 进入主页 -> 跳过已联系 -> 填入自定义文案 -> 自动发送 -> 记录 -> 返回 feed -> 滚动刷新继续 |
| 5 | 保护机制 | 需 autoSendEnabled 已开启否则拒绝启动；单会话上限（默认 10，可配置）；连续失败 2 次即停止；随时可手动停止 |

## 3. 明确不做

- 定时启动、跨会话自动恢复连刷（无人值守，红线保留）
- 关注/点赞/评论等其它自动化动作
- 风控对抗（随机指纹、代理池等）

## 4. 验收方式

`tsc --noEmit` 通过；`npm run build` 成功；匿名态 harness 验证悬浮按钮与推荐页视图；
登录态端到端（连刷一轮真实发送）由用户人工验证。
