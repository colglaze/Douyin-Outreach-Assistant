## V0.5.4 发送确认误判修复

- 用户复测确认：多行私信填充已完整（V0.5.3 paste 路径生效），但自动发送后
  连刷不再继续刷下一位。
- 根因：发送确认以"填入时的编辑器节点"为判据；V0.5.3 多行 paste 使 Slate
  模型为多块结构，发送成功后 Slate 整树重渲染**替换 contenteditable 节点**，
  旧节点断开被误判为"发送未被接受"→ `fail()` 清会话置 ERROR，连刷停止
  （消息可能实际已发出）。
- 修复（详见 BUG-20260903-05 V0.5.4 节）：
  - `waitForInputClear` 节点断开后改查当前可见 surface 的编辑器判空；
  - `sendMessage` 落判前重新探测最新 surface，编辑器已空即确认发送；
  - `sendMessage` 恢复实测成功路径：聚焦编辑器后，同轮激活发送 SVG 与宿主；
  - 推荐 feed 切换下一条改为激活真实控件
    `[data-e2e="video-switch-next-arrow"]`；登录态探针确认播放索引 0→1、
    下一视频进入可视区、作者链接 2→3；旧合成 ArrowDown/WheelEvent 确认无效。
- 版本号升至 0.5.4（main.ts / build.mjs / package.json）。
- `tsc --noEmit` 与 `npm run build` 均已通过，构建产出 v0.5.4
  `dist/douyin-outreach.user.js`；匿名态被动注入 30 秒冒烟通过：fab/panel/达人解析稳定，
  脚本自身无异常（2 条 React hydration pageerror 为抖音页面既有错误）；用户侧以
  dist 内 `@version 0.5.4` 为准导入复测。
- 复测要点：`send confirmed (input cleared)` 或 `send confirmed (editor replaced...)`
  出现后应继续 `message dialog closed -> sent N/M -> 返回推荐页` 循环。

## V0.5.3 多行填充修复（最新）

- 用户反馈：多行私信填充后只留下“你好 高原奇迹所，”首句，正文缺失，未自动发送。
- 根因：Slate 编辑器对单次 `insertText` 在首个换行截断；旧校验仅检查非空或前缀。
- 修复：多行文案优先走 `paste`（text/plain + text/html），填入后做完整规范化比对，不完整则回退逐行插入，仍失败则判填入失败且不发送；单行仍走已验证的 insertText。连刷链路记录渲染长度便于核对。
- `npm --prefix douyin-outreach run typecheck` 与 `npm --prefix douyin-outreach run build` 已通过；需导入最新 v0.5.3 dist 后复测。


- 针对用户复测仍出现的“达人主页后聊天层卡住、视觉有字但发送空消息”，补齐多个残留 IM dialog 场景：
  - 适配层统一选择当前可见 `MessageSurface`，输入框/发送按钮绑定同一 dialog；
  - 移除隐藏输入框回退，改用可见性检查替代 `offsetParent`；
  - Slate 填入前将 Selection 锚定到目标编辑器，填入和发送期间校验节点未被替换；
  - 达人页续跑等待解析出的 secUid/昵称，避免骨架屏 h1 触发过早操作。
- `npm --prefix douyin-outreach run typecheck` 已通过；真实 IM/Slate 发送仍需用户更新脚本后登录态复测。
- 详细记录：`docs/BUG-20260903-05-im-surface-race.md`。


- 用户更新脚本后截图复测：主页仍无悬浮按钮、无错误横幅。本地代码走查确认
  V0.5.0 渲染链路无缺陷，推断根因在"脚本未更新/未注入"一侧，但远程无法确认，
  故做诊断加固（详见 BUG-20260903-03）：

  3. window error/unhandledrejection 全局兜底（fab 缺失时才弹横幅，防误报）；
  4. body 等待改 MutationObserver + 5s 超时；2s 巡检自愈重挂载；防重复注入。
- `tsc --noEmit` 零错误；构建产出 v0.5.1（80.5kb）。
