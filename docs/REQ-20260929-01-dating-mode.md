# REQ-20260929-01 — 交友模式

> 用户需求（2026-09-29）：增加交友功能，按性别、粉丝量选择对象并私信。

## 范围

- 设置中选择商务/交友模式；交友模式配置目标性别（不限/男/女）、粉丝数上下限、独立私信文案。
- 推荐页沿用现有手动启动的连刷流程，在打开私信前根据达人主页资料筛选；不匹配或资料未知时跳过，不计连续失败。
- 性别只读取主页明确的文字或辅助标签，不用头像、昵称、简介推断；目标性别为“不限”时可接受性别未知。
- 粉丝数未解析成功时跳过，不把未知数误认作 0。
- 当前达人面板显示识别结果和交友筛选结果，支持手动私信。
- 若主页不显示性别，用户可在该主页人工标记并保存到本地达人库；此标记优先于自动读取，可清除。
- 默认交友文案保持礼貌、无商业联系方式，允许对方不回复；现有去重、发送上限和停止机制继续生效。
- REQ-20260929-05 增加持续连刷入口后，交友模式原有 50 主页上限仅适用于限量模式；持续模式仍保留筛选、去重与错误停止。

## 不做

- 不通过隐含资料推断性别、年龄或交友意愿；不创建约会资料库或匹配算法。
- 不改变现有自动发送开关的默认值，不做定时启动、验证码或风控规避。

## 验收

- 模式和筛选设置持久化；交友模式选“不限”时粉丝区间生效，选定性别时未知性别跳过。
- 未匹配对象不打开私信、不记录发送；匹配对象使用独立文案和原有发送上限。
- TypeScript 类型检查及构建通过；登录态真实页面链路需人工复测。
