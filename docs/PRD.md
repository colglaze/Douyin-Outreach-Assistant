# PRD — 抖音达人商务助手（Douyin Outreach Assistant）

> 产品总纲，永久保留。来源：《抖音达人商务私信助手项目计划书》。

## 1. 产品定位

不是"自动私信脚本"，而是 **基于浏览器脚本的达人商务拓展 Copilot**：

- 系统负责：识别、整理、生成、填充、记录、提醒。
- 用户负责：确认、判断、发送。

## 2. 要解决的问题

运营人员在抖音网页版寻找达人时，需要在抖音、Excel、AI 聊天工具和 CRM 之间反复复制粘贴：查看达人资料、复制话术、改昵称、打开私信、记录联系状态。本产品把这些重复操作收敛到一个悬浮面板中。

## 3. 目标工作流

```
达人发现 → 达人信息整理 → AI生成私信 → 私信辅助 → 联系记录 → 回复跟进 → 达人CRM
```

## 4. 技术路线（三级演进）

| 阶段 | 形态 | 存储 | 说明 |
|------|------|------|------|
| Phase 1 | Tampermonkey 用户脚本（TS） | IndexedDB | MVP，无后端，验证 DOM 链路 |
| Phase 2 | Chrome Extension MV3 | chrome.storage + IndexedDB | 正式产品，Side Panel |
| Phase 3 | Extension + FastAPI 后端 | PostgreSQL | AI Gateway / 云端 CRM / 团队协作 |

## 5. 三个核心（资源有限时优先保证）

1. **Douyin Adapter** —— 所有抖音页面交互的底座。
2. **Creator CRM** —— 谁联系过 / 何时 / 说了什么 / 有没有回复，业务价值所在。
3. **AI Outreach** —— 基于达人资料生成不像群发广告的个性化私信。

## 6. 最大技术风险

不是 AI，而是 **抖音页面能否稳定识别和交互**。因此开发优先级：先跑通"达人主页 → 识别昵称/粉丝 → 找到私信按钮 → 打开私信 → 定位输入框 → 稳定写入文本"链路，再做 CRM、模板、AI。

## 7. 产品红线

辅助而非托管。默认不执行无人确认连续发送、验证码处理、风控绕过。发送必须人工确认。
