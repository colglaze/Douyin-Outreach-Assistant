# REQ-20260903-01 — 消息自动发送开关

> 关联：REQ-20260902-01（MVP 范围冻结，本需求修订其自动化边界）、REQ-20260902-02（设置面板）、AGENTS.md 第 6 节。
> 状态：已确认（2026-09-03 用户明确授权修订产品红线并实现）。

## 1. 背景

V0.3 的自动化边界为"脚本只填入，发送永远人工点击"（AGENTS.md 第 6 节红线）。
实际使用中，"填入 -> 切回 IM 窗口 -> 手动点发送"动作重复且无判断价值（内容已经过
模板变量与人工校对），用户于 2026-09-03 明确要求：新增一个**控制消息自动发送的开关**，
支持启用与禁用，并明确开关状态的存储位置与生效范围。

**红线修订**：AGENTS.md 第 6 节由"发送按钮永远由用户人工点击"修订为
"默认人工点击；用户可在设置中开启单次自动发送。仍然禁止：连续/批量无人值守发送、
验证码处理、风控绕过"。

## 2. 开关定义（明确项）

| 项 | 定义 |
|----|------|
| 字段名 | `autoSendEnabled: boolean`（`AppSettings`） |
| 存储位置 | IndexedDB `douyin_outreach` 库 -> `settings` store -> key `'app'`（与全部配置同一条记录，经 `storage/settings.ts` 读写与缓存） |
| 默认值 | `false`（禁用，保持人工点击） |
| 生效范围 | **全局持久**：本浏览器全部达人页、全部模板生效；刷新页面/重启浏览器后保持；不分达人、不分模板、无会话级覆盖 |
| UI 入口 | 面板头部 ⚙ -> 设置视图 -> "自动发送"区（独立开关，即时保存） |
| 行为 | 开启后，"填入私信"成功（输入框写入 + 联系记录落库）时自动点击一次 IM 发送按钮；消息状态记为 `SENT`。禁用时行为与 V0.3 完全一致（`FILLED`，人工发送） |

## 3. 纳入范围

| # | 功能 | 验收标准 |
|---|------|----------|
| 1 | 设置项与存储 | `autoSendEnabled` 持久化到 settings store，默认 `false`，重开页面后状态保持 |
| 2 | 设置视图开关 | 设置视图展示"消息自动发送"开关，切换后立即保存并 toast 提示 |
| 3 | 自动发送执行 | 开启时填入私信后自动点击发送按钮，成功 toast、消息状态 `SENT`；发送按钮未找到时 toast 报错且不改变状态 |
| 4 | 禁用回退 | 关闭时不产生任何自动点击，链路与 V0.3 一致 |

## 4. 明确不做（边界仍然收紧）

- 连续/批量自动发送、队列、定时群发（红线保留）
- 发送结果回执抓取（是否真的到达，仍以人工在 IM 窗口确认为准）
- 按达人/按模板粒度的开关覆盖（全局单一开关）
- 发送按钮选择器的真实页面取证校准（沿用候选数组降级 + 文本兜底，待用户日常使用中如失准按 WORKFLOW 第 6 节记 BUG）

## 5. 验收方式

`tsc --noEmit` 通过；`npm run build` 成功；开关默认关闭时行为与 V0.3 一致；
开启后真实页面人工验证一次"填入 -> 自动点击发送 -> 记录 SENT"。
