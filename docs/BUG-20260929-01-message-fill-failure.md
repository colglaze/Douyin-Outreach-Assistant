# BUG-20260929-01 — 持续连刷提示“私信填入失败”

> 关联：REQ-20260929-05、BUG-20260903-04、BUG-20260903-05。

## 现象与取证

- 用户报告持续连刷进入达人私信阶段后，面板显示“私信填入失败”，未继续自动发送。
- 2026-09-29 在临时抖音页面核对：当前聊天编辑器仍有 `data-slate-editor` 与 `contenteditable`，内部文本为 `.ace-line > [data-string]`；多行测试文本被拆成多个 `.ace-line`，`textContent` 没有字面换行。未点击发送，测试草稿已清空。
- 现有 `fillMessage` 在等待编辑器更新后，仍检查最初捕获的 input；编辑器重绘换节点时即返回失败。该判断与发送后已采用的“重新查询可见编辑器”处理不一致。由于未取得用户实际浏览器的控制台日志，这是一处明确的误判风险，不能断言它是本次唯一原因。

## 修复与验收

1. 写入后以当前可见聊天 surface 的编辑器核对完整文案；等待短时间供受控编辑器同步。若首次插入不完整，在当前编辑器只尝试一次替代写入路径。
2. 保持 Slate 安全写入，不直接设置 `innerHTML` 或 `textContent`；仅完整文案通过校验才允许进入发送。
3. 连刷填入仍失败时，停止会话并保留私信窗口和草稿，让用户检查；不关闭窗口后跳去下一位达人。
4. 增加编辑器节点被替换的回归测试，运行类型检查、测试和构建。真实 Tampermonkey 连刷需用户在已登录页面复测。
